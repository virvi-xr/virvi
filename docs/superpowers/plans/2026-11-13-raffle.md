# Raffle Wheel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hosts run opt-in raffles. Visitors with a verified wallet enter from inside a Decentraland scene, the host snapshots who's present, and the server draws winners fairly. Everyone in the scene watches a wheel land on them.

**Architecture:**
- **Server:** new `apps/server/src/raffles/` (service, draw algorithm, routes, sweeps) and a shared `apps/server/src/presence/attendance.ts` that BEAT will reuse. Four new tables. Events go out on the existing venue bus to every room of the scene.
- **Dashboard:** a Raffles tab on the scene page.
- **In-world:** a visitor overlay (raffle card, consent and wheel) and a host Raffle tab, in `packages/adapter-dcl`. They ship as `@virvixr/dcl` 2.15.0 and runtime v14 (the final task).

**Tech Stack:** Fastify, drizzle and Postgres, Colyseus and the Redis bus, vitest, Next.js static export, Decentraland SDK7 React-ECS.

**Spec:** `docs/superpowers/specs/2026-11-13-raffle-design.md`. Read all of it, including **Settled details** at the end, which overrides the text above it.

## Review Focus

1. **A visitor who joins after the raffle opened, or reconnects mid-event,** must still see the card and their entered state. Covered by `GET /api/scenes/:sceneId/raffle/current` returning `myEntry`, tested in Task 5.
2. **A draw when nobody qualifies** (no snapshot taken, or every entrant is under the minimum) must refuse with `empty_pool` and no draw record. It must never pick from all entrants. Tested in Task 4.
3. **Two instances running the auto-snapshot sweep at the same moment** must make one snapshot, not two. Tested in Task 6.
4. **A deleted or withdrawn entrant who was in an earlier draw:** the record still replays to the same winners, and the dashboard shows "withdrawn entrant". Tested in Tasks 2 and 6.
5. **A visitor's display name containing control characters, a very long name, or markup:** it's trimmed to 40 characters, with control characters stripped, before it's stored. Every UI renders it as plain text. Tested in Task 5.

### Task 2: The draw algorithm (pure)

**Files:**
- Create: `apps/server/src/raffles/draw.ts`
- Test: `apps/server/test/raffle-draw.test.ts`

**Interfaces:**
- Produces:
  - `type PoolEntry = { entryId: string; tickets: number }`
  - `buildPool(mode: RaffleMode, snapshots: { entryIds: string[] }[], exclude: Set<string>): PoolEntry[]`. Sorted by `entryId` ascending; entries with 0 tickets are dropped.
  - `drawWinners(pool: PoolEntry[], count: number, seedHex: string, drawId: string): string[]`. Returns the winners' entry ids in draw order.

Algorithm (spec, Settled details 6), deterministic:

```
total = sum(tickets)
for k = 0, 1, 2, … while winners < count and pool not empty:
  r = first 8 bytes of HMAC-SHA256(key = Buffer.from(seedHex, 'hex'), msg = `virvi-raffle:${drawId}:${k}`), as a big-endian BigInt
  limit = (2n**64n / BigInt(total)) * BigInt(total)
  if r >= limit: continue        // rejection sampling
  x = r % BigInt(total); walk the cumulative tickets in pool order; the entry where x falls wins
  remove that entry from the pool; total -= its tickets; append its id
```

If `count >= pool.length`, it still runs the loop, so the result comes out in draw order.

- [ ] **Step 1: Write failing tests**
  - **one_per_person:** three snapshots `[a,b] [b,c] [c]` → pool `a:1, b:1, c:1`.
  - **weighted:** the same snapshots → `a:1, b:2, c:2`.
  - **exclude:** `exclude={b}` removes b.
  - **Same inputs:** the same seed and draw id give the same winners twice.
  - **Different draw id:** gives (for the fixture seed) a different first pick.
  - **No duplicates:** `count=2` over a weighted pool never repeats an id.
  - **Count over pool size:** `count=5` over a 3-entry pool returns all 3.
  - **Empty pool:** returns `[]`.
  - **Distribution:** for a weighted pool `a:1, b:3`, over 4000 draws with seeds `i.toString(16).padStart(64,'0')`, b wins first between 70% and 80% of the time.
  - **Known answer:** for seed `'00'.repeat(32)`, draw id `'d1'` and pool `a:1, b:1, c:1`, `count=3`, assert the exact order the implementation produces. Compute it once, then pin it. It's the published v1 test vector, and it also goes in the docs (Task 9).
- [ ] **Step 2:** Run: they fail.
- [ ] **Step 3:** Implement with `node:crypto` `createHmac`.
- [ ] **Step 4:** Run: they pass.
- [ ] **Step 5:** Commit `feat(raffles): replayable draw algorithm v1 (LIV-55)`.

Validation errors are 400 with a `code`:
- `name_required`, at most 80 characters;
- `prize_required`, at most 200 characters;
- `rules_too_long`, more than 4000 characters;
- `winners_out_of_range` (1 to `RAFFLE_WINNERS_MAX`);
- `bad_mode`;
- `min_present_out_of_range` (0 to 120 minutes; default 5);
- `bad_auto_snapshot` (null or in `AUTO_SNAPSHOT_MINUTES`);
- `host_terms_required`.

A transition from the wrong status is 409 `bad_status`.

**Interfaces:**
- Produces, used by Tasks 5, 6, 7 and 8:
  - `takeSnapshot(raffleId: string, trigger: 'manual'|'auto', now = new Date())`
  - `drawRaffle(raffleId: string, actorUserId: string, snapshotIds?: string[], now = new Date())`
  - `publicRaffle(row): PublicRaffle`. This is what visitors may see: `{id, sceneId, name, prize, rules, status, winnersCount, entryCount}`, with no names.
  - `PublicDraw`: `{drawId, raffleId, names: string[] /* ≤ WHEEL_MAX_NAMES, always including winners, + more count */, more: number, winners: {entryId, displayName}[]}`
  - `emitRaffleChanged(sceneId)`, debounced to once every 2 s per scene.

**Draw rules** (Settled details 6 and 7), all in one transaction:
- `SELECT … FOR UPDATE` on the raffle.
- 409 `draw_in_progress` if `last_drawn_at` is within `DRAW_COOLDOWN_MS`.
- The pool comes from `buildPool` over the chosen snapshots. It excludes earlier winners and entries that no longer exist (withdrawn).
- An empty pool gives 409 `empty_pool` and stores nothing.
- `seed = randomBytes(32)`; `drawWinners(pool, winnersCount, seed, drawId)`.
- Insert the draw. Set `status='drawn'`, `first_drawn_at` (if null) and `last_drawn_at`.
- After the commit, publish `raffle_draw`.

**Snapshot rule:** the entries where `isPresent(row, now, raffle.min_present_seconds)`. An empty snapshot is allowed and stored. Opening sets `next_auto_snapshot_at = now + interval` when an interval is set.
